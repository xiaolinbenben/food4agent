# 💣 痛点流 · 用户差评分析

## 来源标识

| 字段 | 值 |
|------|----|
| 来源方法 | `💣痛点流` |
| 来源渠道 | `用户评论分析` |

## 目标

从用户差评中发现高频痛点，找到 **2件** 能有效解决该痛点的改良型商品。

---

## 执行步骤

### Step -1：Bitable Bootstrap（取 token）

执行 `gateway config.get path=skills.entries.clawshop-data-manager.env`，
取出 `CLAWSHOP_APP_TOKEN` 和 `CLAWSHOP_TABLE_ID`，
然后调用 `feishu_bitable_list_fields(app_token, table_id)` 验证连通性。
- 成功 → 继续
- 失败 → 按 `clawshop-data-manager/SKILL.md` Step 3 重新建表

### Step 1：挖掘用户痛点

使用 `web_search` 搜差评/吐槽（每次**换品类**，参考 memory/clawshop-learnings.md 避免重复）：

**搜索词模板**（按精准度从高到低）：
- `「[品类] 差评 [痛点词]」` ← **最精准**，直接命中高频痛点
- `「[品类] 吐槽 不好用 原因」`
- `「买了[品类]后悔 问题 质量」`

> 💡 带具体痛点词比泛搜「差评」命中率高 3-5 倍，参考常见痛点词选词。

**品类轮转池**（每次选 **3 个不同品类并发搜索**，效率翻倍）：
- 车载摆件 · 桌面摆件 · 解压玩具 · 钥匙扣
- 家居挂件 · 收纳小物 · 创意礼品 · 香薰摆件

**常见痛点词**：
容易倒 / 掉色 / 不稳 / 脱胶 / 异味 / 做工差 / 磁力弱 / 声音大 / 褪色 / 占地方

**季节特别关注**：新品上市差评最新鲜（刚上市 1-2 个月的踩坑反馈质量最高）

### Step 2：归纳高频痛点

从搜索结果中识别：
- 同一类痛点出现 ≥ 3 次 → 确认为高频
- 记录痛点描述（精确，不笼统）

### Step 3：找改良商品

针对识别出的痛点，搜能解决该问题的改良产品：

```
web_search: 「[品类] [解决方案关键词] 防[痛点] 设计」
web_search: 「[品类] 改良版 加重/防掉色/防滑 评测」
```

**入选标准（软过滤）**：
- 产品描述/卖点中明确提到解决该痛点
- 1688 能找到类似货源（可在搜索结果中判断）
- 非极小众品（有一定受众）

**🚨 高风险品类一票否决**（命中任一条 → 直接跳过，不入库）：
- 涉及安全认证强要求：食品接触类、儿童玩具3C认证、电子类CCC认证
- 涉及成分安全争议：硅胶材质解压玩具（甲醛/TVOC风险）、香薰精油类
- 监管灰色地带：仿食品外观玩具、含液体/粉末填充物

> ⚠️ 例外：如果改良品的核心卖点**就是**解决安全问题（如「食品级+3C认证」），
> 可以入库，但**必须**在评估备注加「❗上架前须索取供应商质检证书」，
> 并将候选状态标为「⏳待评估」，由店主人工确认后再铺货。

### Step 4：入库前查重

调用 `feishu_bitable_list_records(app_token, table_id)` 拉全量，
商品名关键词匹配（任意状态）→ 已存在则跳过，换下一个候选品。

### Step 5：入库

`评估备注` 填写：

```
解决痛点：[具体痛点描述]
改良方案：[商品如何解决，1句话]
痛点来源：[搜索词 + 出现频率]
预估售价：¥X / 预估进价：¥X / 加价率：X%
[如高风险品类] ❗上架前须索取供应商质检证书
```

### Step 6：汇报补充

- 本次分析的品类 + 发现的高频痛点
- 每件商品名 + 解决的核心痛点
