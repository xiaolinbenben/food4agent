# 执行流程 v4.2.0

> **核心原则**: 渐进式深化 — 检索→推理→再检索，逐步逼近最优答案

---


## 第一阶段：上下文预处理

> **每次搜索前必须执行**，确保查询意图完整

### 1.1 指代消解

```
检测指代词: "它/这个/那个/前者/后者/上面/刚才/之前说的"
→ 从前轮对话提取最近实体
→ 替换指代词为实体
→ 优先级: 最近出现 > 语义角色匹配 > 频率最高
```

### 1.2 口语规范化

```
"X怎么办"     → "X解决方法"
"X好不好"     → "X评价推荐"
"X靠谱不"     → "X可靠性评价"
"整一个X教程" → "X入门教程"
"X咋搞"       → "X操作方法"
"X多少钱"     → "X价格查询"
"X和Y哪个好"  → "X Y对比评测"
"这玩意儿"    → "这个产品/技术"
"有没有X"     → "X推荐"
```

### 1.3 否定意图提取

```
检测: "除了/不想/不要/排除/去掉/别/非/不包括"
→ 提取排除项
→ 生成排除过滤器
→ 搜索结果中过滤排除项
```

### 1.4 多意图拆分

```
IF 查询含多个领域关键词:
  → 拆分为独立子查询
  → 按领域分别路由
  → 结果合并输出
```

### 1.5 查询扩展

```
同义词替换: "手机" → "手机 OR 智能手机 OR mobile"
领域术语补充: "AI" → "AI OR 人工智能 OR artificial intelligence"
否定词保留: "非CSDN" → 保留排除逻辑
```

### 1.6 话题切换检测

```
IF 当前查询领域 ≠ 前轮查询领域 (连续2轮):
  → 清空旧上下文
  → 开始新话题
  → 保留用户画像（偏好/专长）
```

## 第二阶段：检索执行

### 迭代检索策略

| 轮次 | 目标 | 引擎选择 | 时间筛选 |
|------|------|----------|----------|
| 第1轮 | 广泛召回 | P0引擎 + 通用引擎 | 新闻类自动附加时间参数 |
| 第2轮 | 精准补充 | P1引擎 + 垂直引擎 | 根据缺口决定 |
| 第3轮 | 深度验证 | 官方来源 + 权威媒体 | 精确时间范围 |

### 时间筛选集成

```
新闻查询: 自动附加时间参数
  → 百度: &rtt=1&bsst=1 (按时间排序)
  → Brave: &tf=pw (过去一周) / &tf=pm (过去一月)
  → Google: tbs=qdr:w (一周) / tbs=qdr:m (一月)

历史查询: 不附加时间参数

技术版本查询: 附加近一年筛选
  → Google: tbs=qdr:y
```

### 并行执行规则

```
简单查询: 1个P0引擎
中等查询: 2个引擎并行（P0 + P0/P1）
复杂查询: 3个引擎并行（P0 + P0 + P1）
超时: 单引擎≤5秒，并行≤8秒
最大并行数: 3个引擎
```

## 第三阶段：信息缺口分析

### 缺口检测维度

```
1. 完整性缺口: 关键信息未覆盖（数据缺失、时间缺失）
2. 权威性缺口: 缺少官方/权威来源佐证
3. 时效性缺口: 信息陈旧，需最新更新
4. 多样性缺口: 观点单一，缺少对比视角
5. 深度缺口: 原理/背景解释不足
6. 子问题覆盖缺口: 查询含多个子问题，部分未覆盖
```

### 缺口分析示例

```
Round1结果分析: {
  covered: ["补贴金额", "政策时间", "适用车型"],
  gaps: {
    "完整性": "缺少具体补贴计算公式",
    "权威性": "缺少官方政策原文",
    "多样性": "缺少消费者实际获益案例"
  }
}

subQueries: [
  "新能源汽车补贴计算方法官方文件",
  "新能源补贴政策消费者案例",
  "2026购车补贴实际节省金额计算"
]
```

## 第四阶段：迭代控制

| 规则 | 配置 |
|------|------|
| 最大轮数 | 3轮 |
| 终止条件 | 信息缺口已填补 OR 连续2轮无新有效结果 |
| 单轮超时 | ≤5秒 |
| 总超时 | ≤15秒 |
| 快速失败 | 单引擎3次超时 → 切换引擎 |

## 第五阶段：交叉验证 🆕

> **关键信息必须执行交叉验证**

### 触发条件

```
IF 查询涉及以下任一类型:
  → 版本号/发布日期
  → 数据指标（价格/利率/GDP等）
  → 政策法规（生效时间/适用范围）
  → 医学健康（症状/用药/治疗）
  → 法律判例（判决结果/赔偿标准）
→ 必须执行交叉验证
```

### 验证流程

```
Step 1: 从搜索结果中提取关键信息
  → 版本号: "v5.2.1"
  → 日期: "2026-03-15"
  → 数值: "利率4.35%"

Step 2: 多来源对比
  → 统计各来源对同一关键信息的表述
  → 计算一致率

Step 3: 输出验证结论
  ✅ 确认真实 (N个来源一致, 可信度X%)
  ⚠️ 存在冲突 (来源A说X, 来源B说Y)
  ❌ 无法验证 (仅单一来源)
```

### 信息冲突处理

```
IF 多来源信息冲突:
  → 标注冲突点
  → 按来源权威性排序采信
  → 优先级: 🏢官方 > 📰权威媒体 > 👥技术社区 > 📝个人博客
  → IF 官方来源间冲突 → 标注"需人工确认"
  → 提示用户冲突情况
```

## 第六阶段：Rerank评分

### 五维评分体系（v4.2.0权重调整）

| 维度 | 权重 | 评分规则 |
|------|------|----------|
| 相关性 | 30% | 标题匹配 + 语义匹配 + 查询类型适配 |
| 权威性 | 30% | 来源权重（政务1.0→社交0.6） |
| 时效性 | 25% | 自适应时间衰减（新闻T½=24h，学术T½=3年） |
| 完整性 | 10% | 信息覆盖度 + 子问题覆盖 |
| 新颖性 | 5% | 多轮检索新发现价值 |

### 综合评分公式

```
score = (
  relevanceScore * 0.30 +
  authorityScore * 0.30 +
  timelinessScore * 0.25 +
  completenessScore * 0.10 +
  noveltyScore * 0.05
) * roundWeight

roundWeight = { round1: 1.0, round2: 0.9, round3: 0.8 }
```

### 查询类型适配

```
技术查询: 代码示例匹配+权重↑, 纯理论-权重↓
新闻查询: 时效性+10%权重, 权威性+5%权重
学术查询: 引用数+权重, 发表年份衰减更慢
决策查询: 多角度覆盖+权重, 单一来源-权重
```

### 来源类型识别

| 标识 | 来源类型 | 权威性 | 采纳建议 | 验证要求 |
|------|----------|--------|----------|----------|
| 🏢 | 官方来源 | 95-100% | ⭐⭐⭐ 强烈推荐 | 无需交叉验证 |
| 📰 | 权威媒体 | 80-94% | ⭐⭐ 推荐 | 建议与官方交叉验证 |
| 👥 | 技术社区 | 60-79% | ⭐ 可选 | 需与官方交叉验证 |
| 📝 | 个人博客 | 40-59% | ⚠️ 谨慎 | 强烈建议交叉验证 |
| ❓ | 未验证 | <40% | ❌ 不推荐 | 过滤或忽略 |

### 信源权重体系

```
权威政务媒体（政府网、人民日报、央视）  → 权重 1.0
官方学术平台（知网、万方、ArXiv）      → 权重 0.95
医学权威（丁香园、好大夫、PubMed）     → 权重 0.95
法律权威（裁判文书网、法律法规库）      → 权重 0.95
知识百科（Wikipedia、Wolfram）         → 权重 0.9
专业财经（财新、华尔街见闻）           → 权重 0.9
官方数据平台（交易所、官方平台）       → 权重 0.85
教育平台（中国大学MOOC、考研帮）      → 权重 0.85
字节生态（头条、抖音、西瓜）           → 权重 0.8
数据平台（东方财富、同花顺）           → 权重 0.8
专业平台（CSDN、汽车之家、ZOL）        → 权重 0.7
投资社区（雪球、集思录）               → 权重 0.7
社交内容（知乎、小红书、微博）         → 权重 0.6
通用搜索（百度、必应、DDG）            → 权重 0.5
```

> **必须遵守以下输出格式**

### 输出模板

```markdown

   - 采纳: ⭐⭐⭐ 强烈推荐

### 📰 权威媒体
2. **标题** (权威性: 85%)
   - 来源: 📰 媒体名
   - 发布: YYYY-MM-DD
```

## 去重策略

```
1. URL完全相同 → 直接合并
2. 标题相似度>0.9 → 合并，保留权重高的来源
3. 内容SimHash汉明距离<3 → 合并，保留权威性高的来源
4. 同一站点多个结果 → 保留权重最高的2个
5. 否定排除 → 过滤包含排除项的结果
```
