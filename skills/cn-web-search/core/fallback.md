# 失败切换策略 v4.2.0

> **核心原则**: 快速失败，智能降级，结构化重试

---

## 工具选择决策树

```
需要抓取网页内容？
│
├─ 需登录/交互？ ──────────────→ agent-browser (真实浏览器)
├─ 检测到反爬/验证码？ ────────→ agent-browser (绕过检测) 🆕
├─ 需截图验证？ ──────────────→ agent-browser (可视化)
├─ firecrawl/agent-browser 不可用？ → scripts/web_search_v3.py (Python)
│
└─ 其他 90% 场景 ─────────────→ web_fetch (快速抓取)
```

### 反爬自动降级 🆕

```
IF web_fetch返回以下任一信号:
  → 验证码页面（含"验证/滑块/人机"）
  → 403 Forbidden
  → Cloudflare挑战页
  → 空内容+重定向到登录页
→ 自动切换 agent-browser
→ IF agent-browser不可用 → 切换备用引擎
→ IF 备用引擎也失败 → 提示用户
```

### 执行规则

```
简单查询: 1个P0引擎，串行
中等查询: 2个引擎并行（P0 + P0/P1）
复杂查询: 3个引擎并行（P0 + P0 + P1）

并行限制:
  最大并行数: 3个引擎
  单引擎超时: ≤5秒
  并行总超时: ≤8秒
  重试次数: 1次
  结果合并: 按权重排序，去重
```

## 结构化重试策略 🆕

> **搜索失败时，按以下顺序逐步重试**

### 空结果重试

```
Step 1: 放宽关键词
  → 去除修饰词，保留核心词
  → 示例: "2026年新能源汽车补贴政策最新变化" → "新能源汽车补贴政策"

Step 2: 同义词替换重试
  → 替换为同义词/近义词
  → 示例: "手机" → "智能手机" / "mobile"

Step 3: 切换备用引擎
  → 从P0切换到P1引擎
  → 从垂直引擎切换到通用引擎

Step 4: 英文翻译重试
  → 将中文查询翻译为英文
  → 使用英文搜索引擎（Google/Brave）

Step 5: 提示用户
  → "未找到相关结果，建议补充以下信息：..."
  → 提供可能的查询方向
```

### 反爬重试

```
Step 1: 自动切换 agent-browser
Step 2: IF agent-browser不可用 → 切换备用引擎
Step 3: IF 备用引擎也反爬 → 切换到通用搜索引擎
Step 4: IF 全部失败 → 提示用户稍后重试
```

### 质量低重试

```
Step 1: 放宽查询词
Step 2: 切换不同类型引擎（如从社区切到官方）
Step 3: 增加迭代轮数
Step 4: 调整时间筛选范围
```

### 信息冲突重试

```
Step 1: 标注冲突点
Step 2: 优先采信官方来源
Step 3: 搜索更多官方来源验证
Step 4: IF 仍冲突 → 提示用户需人工确认
```

## 异常处理

### 异常类型与处理

| 异常类型 | 处理策略 | LLM行动提示 🆕 |
|----------|----------|----------------|
| 引擎无响应 | 切换备用引擎，记录异常 | `switch_engine: 备用引擎名` |
| 超时 | 重试1次，失败后切换引擎 | `retry_once_then_switch` |
| 结果空 | 放宽关键词，扩大引擎范围 | `relax_query_and_retry` |
| 反爬拦截 | 自动切换agent-browser | `switch_to_browser` |
| 网络异常 | 提示用户，建议重试 | `notify_user_retry` |
| 内容抓取失败 | 启用agent-browser | `switch_to_browser` |
| 结果重复率高 | 放宽查询词，扩大引擎范围 | `broaden_search` |
| 信息缺口未填补 | 提示用户补充查询方向 | `ask_user_direction` |
| 信息冲突 | 标注冲突，优先采信官方 | `flag_conflict_trust_official` |

### LLM友好错误提示 🆕

```
每个错误必须包含 llm_action_hint 字段:

{
  "error_type": "empty_result",
  "engine": "csdn",
  "timestamp": "2026-05-02T10:30:00Z",
  "llm_action_hint": "relax_query_and_retry",
  "suggested_action": "去除修饰词重试，或切换到baidu.com/s?wd=QUERY"
}
```

|------|----------|
| 单引擎请求 | ≤5秒 |
| 并行请求 | ≤8秒 |
| 结果处理 | ≤1秒 |
| 总响应时间 | ≤10秒 |

## 去重策略

```
1. URL完全相同 → 直接合并
2. 标题相似度>0.9 → 合并，保留权重高的来源
3. 内容SimHash汉明距离<3 → 合并，保留权威性高的来源
4. 同一站点多个结果 → 保留权重最高的2个
5. 否定排除 → 过滤包含排除项的结果
6. 多引擎相同内容不同URL → SimHash内容去重+合并
```

## 快速失败机制

```
终止条件判断:
1. 已达最大轮数 (3轮)
2. 信息缺口已填补（模型判断）
3. 连续2轮无新增有效结果
4. 所有引擎均失败 → 立即终止，输出已有结果
5. 单引擎3次超时 → 切换引擎，不继续等待
```

## 熔断器配置 🆕

```
触发条件: 连续8次请求失败
熔断时长: 5分钟
半开状态: 允许1次试探请求
  → IF 试探成功 → 关闭熔断器
  → IF 试探失败 → 继续熔断5分钟
恢复策略: 指数退避 (5min → 10min → 20min)
```
